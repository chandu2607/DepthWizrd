## 1. Scene-scale target: definition + stability (§6/§7)

The per-scene ORACLE scale is the **robust affine slope `a_i`** from `h = a_i·d + b_i` fit over ALL valid pixels of scene *i* -- exactly the Exp-5 per-image oracle's own parameters. It is derived from **JAX-train GT only** and is the quantity we try to PREDICT; it is never a feature and never the deployable answer (§7).

Candidate scale statistics compared on JAX-train for stability (§6):

| a_ols | 102 | 7.726 | 6.941 | 5.199 | 0.673 | 3.560 | 12.865 |

Cross-correlation (Pearson) among candidates: {'a_robust~a_ols': '0.968', 'a_robust~median_ratio': '0.577', 'a_ols~median_ratio': '0.534'}.

**Chosen target: `a_robust`.** per-scene robust affine slope: identical to the Exp-5 per-image oracle parameters, robust to tall-pixel outliers, and directly usable in the reconstruction h = a*d + b. median(h/d) conflates scale with the depth offset and is unstable when depth ~ 0.

## 9. Limitations

- Unofficial DFC2019 mirror, preprocessed nDSM (ground floored to 0); single training city (JAX), single cross-city test (OMA). Scene count is small (per-scene unit): 102/18/120.
- The oracle scale peeks at each scene's GT and is a NON-deployable upper bound.
- Reconstruction uses the frozen relative depth directly (diagnostic), not C_log1p; it measures the value of scale ADAPTATION, not a production accuracy.
- DA-V2 depth is scale/shift-ambiguous; features describe distribution/appearance, not measured geometry. No camera/sensor metadata is assumed (§21/§22).
- This diagnostic does NOT establish final model / ISRO / DSM / DEM / 3D / production accuracy (§26).
